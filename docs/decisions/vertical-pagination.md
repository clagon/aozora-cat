# 縦書きページ分割の方式決定（Plan 003）

**決定**: 縦書きの1ページを CSS multi-column の1列として組み、ブラウザの断片化に境界を任せる（`columns` 方式）。ページ位置は実測した矩形から作る項目表で管理し、位置の識別は「段落番号 + 段落内の文字位置」にする。

**状態**: Chromium と WebKit（Playwright）の全マトリクスは通過。**iPhone Safari と Android Chrome の実機・リモート端末での確認は未実施**で、本番リーダー（Plan 007）の着手前に運営者の確認が必要（後述）。

## 比較した方式と結果

どちらも全フィクスチャ × 4 文字サイズで、欠落・重複・順序違反・境界またぎ・ページ外・空ページ・改ページ位置を数えた（Chromium / WebKit 同結果）。

| 方式                                                                                           | 実フィクスチャ（28件） | 行幅が揺れる合成データ（`edge-cases`）                                     | 採否     |
| ---------------------------------------------------------------------------------------------- | ---------------------- | -------------------------------------------------------------------------- | -------- |
| `columns`: 縦書きの multicol。列の高さ＝ページ高、`break-inside: avoid`、`break-after: column` | 全件通過               | 4/4 通過                                                                   | **採用** |
| `offsets`: ページ幅を行ピッチの整数倍にし、`translateX` と余白で境界を合わせる                 | 全件通過               | 1/4 のみ通過。大きな文字で行ピッチが崩れ、以後のページ境界が累積してずれる | 不採用   |

`offsets` は行ピッチが厳密に一定のときだけ成立する。外字画像の `vertical-align: middle` だけでも行内の字位置が 4.7px ずれ、行端の文字が境界をまたいだ。上流の「大きな文字」記法がある限り前提を保証できない。`columns` は各ページの境界をブラウザが引き直すため、ずれが累積しない。

## 採用した方式の要点

- 縦書きの multicol は列が**縦方向**に積まれる。ページ送りは `transform: translateY(-k × ページ高)` で行い、`overflow: hidden` のステージで1ページ分だけ見せる。
- ページ高は文字サイズの整数倍、ページ幅は行ピッチ（文字サイズ × 2）の整数倍に丸める。
- 横書きは縦スクロール。ページ送りの操作は縦書き時だけ有効にし、横書きではネイティブスクロールに任せる。
- ジェスチャーは、左端20%タップと左スワイプ（水平40px以上かつ縦の1.5倍超）で次ページ、右端20%と右スワイプで前ページ、中央タップで操作バー。縦方向が優位な動きは何もしない。キーボードは `ArrowLeft` / `PageDown` / `Space` が次、`ArrowRight` / `PageUp` / `Shift+Space` が前。
- 動きは `--motion-duration-standard` を使い、`prefers-reduced-motion` では 1ms になる。

## 本番向けAPI契約（コードは Plan 007）

```ts
type Anchor = { p: number; off: number }; // 段落番号と、ルビを除く段落内の文字位置

interface PagedReader {
	readonly page: number;
	readonly pageCount: number;
	readonly anchor: Anchor; // 利用者が最後に置いた位置。再レイアウトで丸めない
	next(): void;
	prev(): void;
	goTo(page: number): void;
	restore(anchor: Anchor): void; // その位置を含むページへ移る
	configure(o: { size?: number; mode?: 'vertical' | 'horizontal' }): void;
}
```

- 文字サイズ・向き・縦横の切替・画面サイズ変更のたびに再レイアウトし、`anchor` を含むページへ復元する。ページ先頭へ丸めた位置を保存し直すと、往復でずれる。
- 保存する位置は段落IDと文字位置。ページ番号は端末・設定で変わるため保存しない。
- 読み込んだ本文は型付きスキーマから描画する。検証用ハーネスは信頼済みの自前フィクスチャだけを `DOMParser` で読む。

## 見つかった落とし穴

| 事象                                                                                                                 | 対処                                                                                                                                                            |
| -------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 行末の全角空白が1字ぶんはみ出す                                                                                      | 見えないので位置判定から外す。「？　」の直後で頻出する                                                                                                          |
| 外字画像やルビ基底の画像は1文字として数える                                                                          | 位置の文字数に含める（`kind: 'img'`）                                                                                                                           |
| 外字の `vertical-align: middle` / `top` が行内の字位置をずらす                                                       | `baseline` にする                                                                                                                                               |
| `text-combine-upright`（縦中横）は文字ごとの矩形が合成グリフに重なる                                                 | 順序判定から外す                                                                                                                                                |
| 文字ごとの `Range.getClientRects()` は、フォントによってはまとまりの矩形を返す（検証環境の既定フォールバックで発生） | 検証は固定フォントで行う。位置表の作成は 2 万字で約 100ms（Chromium）〜 230ms（WebKit）かかるため、本番は行単位の測定か遅延測定を検討する                       |
| ページ送り中にスクリーンショットやレイアウト測定をすると遷移途中を拾う                                               | 測定は常に相対座標で行い、画像確認は遷移後に待つ                                                                                                                |
| 横書きの慣性スクロールが残ったまま縦書きへ戻すと、ステージのスクロール量と `translateY` で二重にずれる               | 縦書きのステージを `overflow: clip` にし、ページ送りのたびに `scrollTop` も 0 に戻す                                                                            |
| 横書きでネイティブスクロールした位置が、縦書きへ戻すときに反映されない                                               | ステージの `scroll` で現在ページと位置を取り込む                                                                                                                |
| `viewport-fit=cover` の実機では本文がノッチやホームインジケータに重なる                                              | ハーネスはトークンの `--content-padding-*`（安全領域つき）を余白に使う。`?safe=上,右,下,左` で安全領域を再現し、縦向き（47,0,34,0）と横向き（0,47,21,47）で検証 |
| 字下げ・地付きは複数行を囲む `div` のクラスにある                                                                    | 抽出時に `--indent` / `--inset` として段落へ残し、折り返した行頭も同じ位置にそろえる                                                                            |
| 横書きのネイティブスクロールの位置は、ページ境界へ丸めない                                                           | `scroll` で、その位置の最初の項目を基準にする                                                                                                                   |
| ジェスチャーの `pointerup` は横書きで無効にしないとスクロールを奪う                                                  | `enabled()` で縦書きのみに限定                                                                                                                                  |

## 未達・要確認

- **実機確認が未実施**: iPhone Safari と Android Chrome の実機またはリモート端末を、この環境では使えなかった（デバイス接続が無効）。端末プロファイルでの代替は、iOS の動的ツールバーや安全領域、実フォントの寸法を再現しない。Plan 003 の STOP 条件「デスクトップ・エミュレーションのみ」に近いため、運営者が実機でハーネス（`prototypes/vertical-reader`。既定は採用方式の `columns`、比較用に `?approach=offsets`）を開いて確認し、結果をここへ追記するまで本方式を確定扱いにしない。
- 明朝系の実フォントでの再測定（特に iOS の `ui-serif`）。
- SvelteKit またはブラウザエンジンを更新したときは、同じマトリクスを再実行する。
